Lead project · scam safety · India

Ruko

Ruko (Hindi for "wait") spots the signs of a phone or WhatsApp scam and stops people at the moment it matters: before they pay.

Try Ruko liveCode on GitHub

The problem

Phone scams in India have moved from "click this link" to live pressure on calls: fake police "digital arrest", seized parcels, blocked SIM cards, a relative "in trouble". Most start as a voice call and many move to a WhatsApp video call with a uniformed "officer". Help today mostly arrives after the money is gone. Victims are often older parents who are alone on the call, and the scam depends on keeping them alone.

What it does

  • Check a message. Paste it, say it aloud in Hindi or English, or add a screenshot. Ruko returns a risk level, the scam type, the exact lines that gave it away, and one clear next step.
  • I'm on a call. Four yes/no questions answered while the caller is still on the line. No AI, so it is instant and cannot invent anything.
  • Call protection (Android, designed). Watches the signs of a scam call without ever hearing it: a stranger, a police-style profile picture, a long call, a payment app opened. It shows a STOP screen at the money moment and alerts a trusted family member.

Try the alert timing

This uses the same tiered rule as the app. Time alone is a weak signal, because customer-care calls run long too, so each warning sign brings the family alert forward.

Key decisions

Rules first, AI second

Red-flag rules in English, Hindi and Hinglish run on the phone instantly and still answer if the AI is down or rate-limited. The AI (Gemini) then classifies into 13 fixed Indian scam types, so answers are consistent and testable.

No made-up evidence

The AI must quote the exact lines it relied on. Code throws away any quote that does not appear in the message.

Never says "safe"

A missed scam costs someone's savings; a cautious answer costs a phone call to family. The best verdict is "no scam signs found, still check before paying". The AI can raise the risk but cannot clear a strong red flag.

Never listens to calls

Phones block call audio for good reasons. Ruko uses only signals the phone can see, and removes names, numbers, UPI IDs, Aadhaar, PAN and account numbers on the phone before any text is sent.

Bring in family, automatically

Scammers win by isolating the victim ("don't tell anyone"). The strongest feature is not detection, it is the alert that ends the isolation.

Improve with a gate, not by itself

Users say whether Ruko was right. A person reviews that feedback, turns it into test cases, and a change ships only if no language group gets worse. Auto-learning from feedback is open to mistakes and to poisoning by scammers.

How I know it works

Test set: 123 real, published messages (97 scams, 26 genuine) from fact-checkers, newspapers, police and bank advisories, each with its source. Nothing invented. The genuine set is small, so false-alarm figures will move as it grows.

The trade-off I chose. Adding the AI tripled the catch rate but raised false alarms, so my own regression gate flagged it. I kept it on purpose: every false alarm was a "Careful, check first" warning on a scary-sounding real bank or tax message, never a STOP. A missed scam can cost someone's savings; a cautious warning costs a phone call. Cutting false alarms is the next iteration.

What still breaks

  • Danger hidden in an attachment, like a wedding "invitation" that is really an app file. The text alone looks harmless.
  • Fake "money credited" SMS that look identical to real ones. Only the bank app can confirm.
  • Short chat messages that only look wrong in context, such as a "boss" asking about company funds in Hinglish.
  • Messages that are only an image or a voice note.
  • iPhone does not allow call protection at all; those users get the web check only.
  • Prevention depends on setup before the scam happens. Adoption, not detection, is the hardest problem.
Second project · beauty e-commerce

Shade Finder

Paste a lipstick link or type a shade, and see it on your face in the live camera before you buy.

Try Shade Finder liveCode on GitHub

What it does

  • Live try-on on the phone. Face tracking (MediaPipe) runs in the browser and paints the shade on the lips. The camera feed never leaves the device.
  • Reads a product link. An AI reads the product page and returns brand, shade and an approximate colour, always labelled as approximate.
  • Tunable realism. Opacity, gloss, edge smoothing, saturation and brightness controls, with presets built from beauty-industry judgment on how balms and lipsticks actually read on lips.

Key decisions

Code for colour, AI for words

Painting the shade is deterministic code, so the same shade always looks the same. The language model is used only where language helps: reading a messy product page.

The AI may not guess

If the page lists many shades and the choice is unclear, the colour comes back empty and the user picks it. Page text is treated as untrusted data, and the reader blocks requests to private networks.

On-device vs cloud try-on

I set up a local comparison with a commercial cloud try-on API. It uploads a face photo, uses paid credits per try, and returns a still image rather than live video. I kept the on-device version as the product; the side-by-side quality comparison is still to run.

What I learned

Try-on is a feature, not a product: it would look the same whoever built it. That pushed me to look for a problem where my judgment, rigour and evidence matter more than the demo, which became Ruko.

How I work

Principles behind both projects

Evidence before claims

Targets are written down before testing, results are reported per group, and every miss is listed.

The right tool for each part

Deterministic code where answers must be consistent and cheap; AI where language and messiness need it.

Private by default

Faces stay on the phone. Personal details are removed before anything is sent. Calls are never heard.

Fairness is measured

Results are split by language and group, because an average can hide who the product fails.

Honest about uncertainty

"I can't tell" and "approximate" are valid answers. Confident wrong answers are the real failure.

Cost is a design input

Both projects run at ₹0 on free tiers and log time and tokens so the paid-scale cost can be estimated.
